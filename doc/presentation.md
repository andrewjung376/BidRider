# BidRadar 입찰레이더

### 나라장터 입찰공고 AI 수집·분석 서비스

- 서비스: **https://bidradar-web-mocha.vercel.app**
- 저장소: https://github.com/andrewjung376/BidRider
- 팀: 팀장 (PM / Backend / AI), 팀원 (Frontend / Data / QA)

<p class="small">코디세이 AI 네이티브 Final Project · 2026-10-15 ~ 10-20</p>

---

## 1. 문제 정의

- 나라장터 공고는 **하루 수백~수천 건** (용역만 하루 약 600건)
- 중소기업 입찰 담당자는 매일 직접 검색하고, 공고마다 **참가자격·추정가격·마감일**을 읽어야 한다
- 기존 알림 서비스는 목록만 준다 → **"우리 회사가 참여할 만한가?"** 는 여전히 사람이 판단

> 목표: **찾는 시간**과 **읽고 판단하는 시간**을 AI로 줄인다

---

## 2. 해결 방식 — "수집은 정확하게, AI는 해석에"

| 단계 | 방법 | 이유 |
|---|---|---|
| 수집 | 공공데이터포털 **나라장터 OpenAPI** | 원천 데이터 그대로, 실시간에 가까움 |
| ~~수집~~ | ~~LLM 실시간 웹 검색~~ | 환각·누락 위험 → 제외 |
| 해석 | **AI 3줄 요약** | 공고를 읽는 시간 단축 |
| 판단 | **적합도 점수·근거** | 회사 프로필 기준 우선순위 |
| 탐색 | **AI 채팅 검색 (Agent)** | 조건을 문장으로 말하면 검색 |

대상: 중소 IT·용역·엔지니어링 업체의 영업·입찰 담당자

---

## 3. 서비스 화면

| 화면 | 기능 |
|---|---|
| 입찰공고 `/bids` | 필터(업무 구분·키워드·기관·금액·마감일), **AI 요약**, 원문·첨부파일 |
| AI 검색 `/chat` | "이번 주 마감 설계 용역 찾아줘" → 공고번호 인용 답변 + 공고 카드 |
| 추천 `/recommendations` | 프로필 기준 **점수·근거**, 👍/👎 |
| 프로필 `/profile` | Google 로그인, 업종·지역·금액·키워드, 동의, **탈퇴** |
| 수집 설정 `/settings` | 업무 구분·건수, **지금 수집** |
| 자동 | **매일 09:00 KST 수집 → 요약** (Vercel Cron) |

## 4. 시스템 아키텍처

```
브라우저 ─► web: Next.js (Vercel 서울) ──/api 프록시──► api: FastAPI (Vercel 서울)
              └ Supabase Auth (Google 로그인만)            ├ 서비스 함수 (수집·검색·추천·프로필)
                                                          ├ Bid Agent ─ 도구 호출 ─► Claude Sonnet 5.5
                                                          ├ 요약·추천 평가 ─────────► Claude Haiku 5.5
                                                          ├ 수집 ─► 나라장터 OpenAPI
                                                          └ Supabase PostgreSQL (RLS)
Vercel Cron (매일 09:00) ─► /api/cron/collect ─► 수집 → 요약
```

- **web은 DB에 직접 접근하지 않음** — 데이터는 모두 FastAPI 경유
- GitHub `main` 병합 → **자동 배포**

---

## 5. AI 활용 ① 자동화 워크플로우 + AI 요약

**Cron → 수집(중복 제거) → 새 공고만 요약 → 저장**

- Claude Haiku 5.5 + **Pydantic 구조화 출력** (3줄 요약·참가자격·제출서류)
- 근거는 나라장터 필드 35개 + 첨부파일명만 → **추측 금지**
- 요약이 실패·시간 초과해도 **수집은 성공**, 남은 공고는 다음 수집 때

실측: Production Cron 10건 수집 **3초** + 요약 10건 **약 8초**

---

## 6. AI 활용 ② Agent + RAG

> 질문: "이번 주에 마감하는 설계 용역 공고 찾아줘"

```json
search_bids { "q": "설계", "category": "용역",
              "closing_from": "2026-10-19", "closing_to": "2026-10-25" }
```

- Claude Sonnet 5.5 **도구 호출 루프** (최대 3단계, 도구 = 기존 서비스 함수)
- 시스템 프롬프트에 **오늘 날짜·요일**, 금액 환산(1억 = 100000000) → "이번 주"·"1억 이하"를 조건으로
- **RAG**: 도구 결과에 있는 공고만 근거로, **공고번호 인용** → 인용한 공고만 카드로 표시
- 이어지는 질문: "그중 금액이 가장 큰 공고는?" → 앞 대화 기억

---

## 7. AI 활용 ③ 맞춤 추천 + Long-term Memory

- 회사 프로필(업종·지역·금액·키워드)로 마감 전 공고를 **0~100점 + 근거** 평가 (Haiku 5.5)
- 예) 토목설계·전남 프로필 → "무안 실시설계 용역" **88점** "토목설계 업종과 직접 맞고 관심 지역 전남"
- **기억하는 것**: 프로필, 👍/👎 → 다음 평가 프롬프트에 반영
- 프로필이 바뀌면 **다시 평가**, 👍/👎는 유지 / 한 번에 10건, 남은 후보는 "더 불러오기"

필수 기술 요소 **4개**: 자동화 워크플로우 · AI Agent · RAG · Long-term Memory

## 8. 기술적 의사결정 근거

| 결정 | 근거 |
|---|---|
| 수집은 OpenAPI, LLM은 해석 | 수집은 결정적이어야 함 (환각 방지) |
| 모델 분리: Haiku(요약·평가) / Sonnet(Agent) | 대량·저비용 작업과 추론·도구 사용 작업을 분리 |
| `LLMProvider` 인터페이스 | 제공자 교체 가능 (OpenAI 등) |
| Vercel 서울 리전 `icn1` | 공공데이터포털 해외 IP 차단 우려 → **실제 호출로 확인** |
| 로그인: 매직 링크 → **Google** | Supabase 무료 메일 발송 **시간당 2통** 제약 |
| 탈퇴 = **Auth 계정 삭제 1회** | 외래키(cascade / set null)가 나머지 정리 → 누락 없음 |
| FastMCP·n8n **제외** | 필수 요건 아님, 5일 일정에서 핵심 기능·테스트 우선 |

## 9. 실측으로 개선한 것

| 발견 | 개선 |
|---|---|
| 요약 문체 혼용, "값이 없다"를 굳이 언급 | 문체 통일·없는 값 생략 지시 → 재생성 |
| 첨부파일명(과업지시서)을 **제출서류**로 분류 | "첨부파일은 발주기관 제공 문서" 명시 |
| 마지막 페이지를 넘으면 **502** | 리뷰 중 발견 → PostgREST 416 처리 (#17) |
| 피드백 폼 **오픈 리다이렉트** | 리뷰에서 2차례 변경 요청 → 우회 경로까지 차단 + 자동 테스트 27건 (#19) |
| 긴 답변 뒤 채팅이 **422** | `history` 4000자 제한 (팀원 발견, #32) |

## 10. 협업 과정

- **팀장**: 기획·계약서·백엔드·AI·배포·리뷰 / **팀원**: 스키마·웹 화면 전체·사용자 테스트·리뷰
- **이슈 → 브랜치 → PR → 상대 역할 리뷰 → 병합**, 커밋 본문에 `담당: 팀장/팀원`
- **데이터·API 계약서**로 먼저 합의 (v1 → v1.1 탈퇴 → v1.2 Agent·추천), 계약 변경은 상대 리뷰 후 병합
- 팀원 리뷰가 설계를 다듬음: 추천 `items` 범위·👍/👎 유지·마감일 없는 공고 등 4건 명시
- 결과: PR **38건**, 이슈 **11건**, 테스트 api **68건** · web **27건**
